Why We Built This

Material science is one of the most complex spaces to navigate for IP. Chemistry families span thousands of overlapping filings. Claim language is deliberately ambiguous. A single domain — say, conductive adhesives for EMI shielding — can touch a dozen subfields, each with its own patent thicket.

The standard answer is: hire a specialist consultant or subscribe to an enterprise patent intelligence platform. Both cost serious money, and both put a researcher or early-stage team at the back of a queue.

Without those resources, we built a tool that follows FTO best practice — using an LLM to read every relevant patent and check whatever hypothesis you need to test. A landscape that would take a consultant two weeks takes a few hours. On your own hardware. Cheaply.

The goal: quickly iterate, inform researchers early, and reduce consultant spend to the decisions that actually need a lawyer.

LLM Analysis — The Core Innovation

Each patent is sent to a local language model with a custom persona prompt.

Persona examples

  • FTO analyst — can we operate freely?
  • Patentability examiner — is there novelty?
  • Licensing officer — what's it worth?
  • Competitor analyst — where is the whitespace?

Each persona produces:

  • H / M / L risk tier per patent
  • Plain-language summary
  • Claim-level reasoning

Why local LLM?

Running 800 patents through GPT-4: ~$200–400

Running 800 patents locally on a university GPU: ~€0 marginal

Models: Qwen, Llama, Mistral — all run on a single A100 or equivalent.

No API keys. No data exfiltration. No usage caps.

Architecture — Open and Extensible

Stack

  • FastAPI — backend API + server-rendered UI
  • SQLite WAL — portable, zero-admin database

  • Docker — one-command deploy
  • Ollama / Atomic Chat — local LLM serving

Extend it

  • Add new analysis views (graph, timeline)
  • Custom LLM prompts per technology domain
  • Scheduled monitoring cron jobs
  • PDF report generation
  • Integration with university CRIS systems

MIT licence. Self-host or collaborate. The architecture is intentionally simple — any developer familiar with Python can extend it.
